# Club Calendar

Native macOS menu-bar app + iOS app that sync Strava club events into Apple Calendar. Swift 6.2 / SwiftUI, no third-party runtime deps.

## Project layout

```
ClubCalendarCore/                 # SPM library — shared by both apps
├── Models/                       #   Club, ClubEvent, Settings
├── Services/                     #   Strava, Calendar, Auth, Sync, Protocols
└── Utilities/                    #   Logger, ActivityEmoji, KeychainHelper

ClubCalendar-macOS/               # macOS menu-bar app (SPM executable target)
├── Sources/
│   ├── App/                      #   ClubCalendarApp (@main), AppState
│   ├── Views/                    #   MenuBarView, SettingsView (+ tabs), OnboardingView
│   └── Resources/                #   Icons, entitlements, Info.plist material
└── Tests/                        #   ClubCalendarMacTests target

ClubCalendar-iOS/                 # iOS app (Xcode project, generated by xcodegen)
├── Sources/                      #   ClubCalendarApp (@main), AppState, BackgroundSync, Views/
├── Tests/                        #   ClubCalendarIOSTests target
├── project.yml                   #   xcodegen spec (truth)
└── ClubCalendar-iOS.xcodeproj    #   generated, gitignored

Package.swift                     #   SwiftPM — declares ClubCalendarCore + ClubCalendarMac targets
Makefile                          #   make {macos,ios}-* targets, see `make help`
docs/                             #   ios-port-plan.md, ios-install.md
```

SPM target names: `ClubCalendarCore` (library), `ClubCalendarMac` (executable), `ClubCalendarMacTests` (test bundle).
Xcode target names: `ClubCalendarIOS` (app), `ClubCalendarIOSTests` (test bundle).
Both apps' user-facing binary is named `ClubCalendar` (PRODUCT_NAME); bundle IDs are `com.clubcalendar.app` (macOS) and `com.clubcalendar.ios`.

All commands below assume `cwd =` repo root.

## Commands

```bash
# macOS
make macos-dev          # build debug, bundle, sign with local dev cert, open
make macos-test         # swift test — runs both Mac + Core tests
make macos-restart      # kill, rebuild, reopen
make macos-logs         # stream unified logs for subsystem com.clubcalendar.app
make macos-dmg          # signed release DMG with /Applications shortcut

# iOS (override sim via IOS_SIM_DEVICE='iPhone 17 Pro')
make ios-gen            # regenerate Xcode project from project.yml
make ios-test           # xcodebuild test on simulator, with coverage
make ios-test-suite SUITE=X  # one iOS test suite, fast, no coverage
make ios-coverage       # print coverage report after ios-test
make ios-run            # build + boot simulator + install + launch
make ios-archive        # signed archive for device install (needs DEVELOPMENT_TEAM=...)
make ios-install-device # install archived app on connected iPhone

# Shared
make test               # full test matrix (macos-test + ios-test)
make macos-test FILTER=X  # only tests matching regex X
make lint               # swift-format lint (config: .swift-format)
make format             # rewrite sources with canonical formatting
```

## Architecture

Both apps wire the same `ClubCalendarCore` services through their own composition root:

```
{ClubCalendarApp macOS / iOS}  (SwiftUI @main)
  └── AppState (@MainActor @Observable)        ← platform-specific
        ├── KeychainHelper                     (Security.framework — file keychain on mac, data-protection on iOS)
        ├── AppSettings                        (@AppStorage + JSON-encoded clubs)
        ├── StravaService (actor)              (api.strava.com — token mgmt + clubs + events)
        ├── CalendarService (actor)            (EventKit; dedup by Strava ID in EKEvent.url)
        ├── AuthService                        (ASWebAuthenticationSession, clubcalendar:// scheme)
        └── SyncService                        (macOS: NSBackgroundActivityScheduler + wake notif;
                                                 iOS: BGAppRefreshTask via BackgroundSyncCoordinator)
```

Sync flow (both platforms): `SyncService.sync()` → `StravaService.getEventsForClubs(...)` → `CalendarService.syncEvents(...)`.

Platform-specific code in `ClubCalendarCore` is gated by `#if canImport(AppKit)` (in `AuthService`, `SyncService`, `Logger`).

## Testing

- swift-testing (`@Test`, `@Suite`) is the default; some XCTest cases remain in `ClubCalendar-macOS/Tests/`.
- Mocks live in `ClubCalendar-macOS/Tests/Mocks/` and `ClubCalendar-macOS/Tests/ServiceTests/Mock*.swift`. They conform to the protocols in `ClubCalendarCore/Services/Protocols.swift`.
- HTTP is mocked via `MockURLSession` (injected into `StravaService`).
- iOS tests live in `ClubCalendar-iOS/Tests/` (`AppStateTests`, `BackgroundSyncTests`, `ViewTests`, `TestHelpers`). They use the real `KeychainHelper.shared` + `AppSettings.shared` against the simulator's sandbox, wiped between suites.
- Keep tests at the protocol boundary; no internal mocking.
- `CalendarServiceIntegrationTests` (iOS) hit a real `EKEventStore` and skip silently without calendar permission; `make ios-test` pre-grants it via `simctl privacy`.
- xcodebuild `-only-testing` matches swift-testing `@Suite` types at the suite level only; function-level identifiers silently match nothing. Use `make ios-test-suite SUITE=X`.
- `make ios-test` failures print only a summary; rerun the suite via `make ios-test-suite` (or `ios-test-verbose`) to see which `#expect` failed.

## Gotchas

- `EKEventStore.events(matching:)` returns events in no particular order; sort before `prefix()`.
- EKEventStore persists dates with whole-second precision; compare via `CalendarService.startDateTolerance`, never exact `==`, or every sync reports spurious updates.
- `EKEvent.title`/`startDate`/`notes` are IUOs that can be nil (user-edited events); empty `notes` normalize to nil.
- Never call `KeychainHelper` from the main actor on macOS: after a cert rotation, each read blocks inside a SecurityAgent ACL prompt, and a blocked main thread while the menu-bar menu is tracking freezes keyboard input system-wide. `AuthService`'s keychain-only methods are `nonisolated @concurrent` for this reason; `AppState.refreshState()` hops via `Task.detached`.
- Calendar (TCC) grants and keychain ACLs are tied to the "ClubCalendar Development" signing cert. Always sign with it, never ad-hoc: a rotated identity resets the user's permissions (see README "Permissions across installs and updates").
- After changing `ClubCalendarCore` public API, SourceKit/LSP diagnostics in dependent targets are stale until the next `swift build`; trust the build, not the stale diagnostic.

## Rules

- Never build a DMG (`make macos-dmg` / `make macos-release`) or an iOS archive (`make ios-archive` / `make ios-install-device`) without an explicit request.
- Never push to a remote unless asked, and never to a remote that isn't `github.com/konradko/*`.
- macOS 26 minimum, iOS 26 minimum — feel free to use new APIs (`Date.FormatStyle`, `ASWebAuthenticationSession`, `@Observable`, `BGAppRefreshTask`, `ContentUnavailableView`, etc.). No availability guards needed.
- After non-trivial changes, run `make macos-test` AND `make ios-test` (or at minimum `swift build`) before reporting done.
